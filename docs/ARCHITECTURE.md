# QPanes — Architecture decisions (initial)

## Layers

1. **Svelte 5 view layer**: display, local presentation state, focus and keyboard interactions, animations and styling.
2. **Typed Tauri IPC adapter**: request/response validation and orchestration, no filesystem business logic.
3. **Rust filesystem core**: directory discovery, path handling, metadata, sorting behavior if needed by the domain, and eventually safe file operations.

Core functions should be testable in isolation using temporary directory fixtures. Extract into `crates/qpanes-core` when implementing the first substantial filesystem behavior. Do not introduce a generic filesystem-provider trait before there are two providers or a concrete testing need.

## Current project structure
Use the directories and build scripts actually generated by create-tauri-app. The Svelte template may contain SvelteKit; that is fine as long as it emits a static client-side bundle compatible with Tauri. Do not add an HTTP backend or SSR runtime.

## Cross-platform correctness
- Rust `Path` / `PathBuf` semantics differ across operating systems. Do not manipulate native paths by splitting on `/` or `\\` in JS.
- Non-UTF-8 filesystem paths are possible on Linux. Design a safe representation without silently treating lossy labels as filesystem identifiers.
- A symbolic link must not create uncontrolled traversal loops.
- Tests must include permission errors, disappearing paths, empty directories, unicode names, and stale asynchronous results.
- Development under WSL exercises Linux behavior; Windows and macOS require target-native verification prior to release.

## Safety and trust
- No arbitrary shell access through Tauri IPC.
- Future mutating operations must surface conflict policy and avoid silent overwrites.
- Future MCP should reuse the Rust core but must enforce explicit scope/permissions and separate trusted client access.

## Slice 001 decisions

- `crates/qpanes-core` is a standalone Rust library with only Serde. The existing desktop crate depends on it by path. Each crate keeps its own lockfile; `mise` checks both manifests explicitly. No workspace migration or new frontend dependencies were needed.
- `list_directory` accepts a Serde request and returns a listing or structured error. `sort_directory_entries` reorders an existing array of real entries using the same core comparator, without filesystem I/O. Both commands are thin blocking-pool adapters; the TypeScript contracts live in `src/lib/filesystem.ts`.
- Native identifiers contain platform-tagged hexadecimal Unix bytes (`u:`) or little-endian Windows UTF-16 (`w:`). Display names/paths may be lossy; they are never converted back into identifiers. An unchanged path input uses the current native identifier. User-edited absolute paths are explicit typed targets.
- Paths are canonicalized. Parents stop at the native root (including Windows drive/UNC roots). Symlink rows use link metadata and cannot be opened. Explicit typed paths may resolve symlinks; canonicalized parents then describe the resolved location. No recursive traversal exists.
- Sorting is directory-first in both directions. Name order compares Unicode lowercase, exact name and native identifier; it is deterministic rather than locale/natural sorting. Size/date unknowns stay last; ascending name order breaks ties. Lowercase keys are cached during sorting.
- Every pane owns its path, selection, sort, scroll and request sequence. Older responses are discarded. Failed navigation keeps the last successful contents and exposes the failure and attempted input. Sorting and refresh preserve selection by native identifier; parent navigation selects the child just exited.
- Lists use 32px rows and eight rows of overscan on each side, with raw Svelte state for listing payloads. A 10,000-entry renderer fixture produced 23 rendered options at 1200×780. Rust still enumerates, reads metadata and sorts the complete directory; IPC and memory are O(n), sorting O(n log n). Pagination, cancellation and incremental metadata remain possible measured follow-ups.
- Tab switches panes from a file list; Shift+Tab retains normal traversal to toolbar controls. Ctrl/Cmd+L edits the active path; Escape returns to the list. Arrow keys, Enter, Backspace, Home/End and Page Up/Down operate on the list. A slider exposes horizontal panel resizing to keyboard and pointer input.
- Verification separates Playwright CLI with deterministic mocked IPC from real WebKitGTK/Tauri IPC under WSLg. The native smoke script uses a localhost debug inspector and DOM-dispatched input, without production test hooks or weakened app security. Trusted keyboard input is covered in Chromium; native OS key delivery, Windows and macOS remain manual/release QA.

## Slice 001 acceptance hardening

- Sorting an already loaded directory sends its real entry array to the pure Rust sorting command. This avoids re-enumeration and preserves the domain's single sorting implementation, at the cost of an O(n) IPC round trip. No frontend filesystem/provider abstraction or dependency was introduced.
- Sort preferences are independent from the navigation sequence. During an active navigation or sort, further preference changes are coalesced. The arriving listing is sorted to the latest preferences before committing; a newer navigation invalidates either kind of older response. Sort changes never select a destination or issue a directory read.
- View rows form a discriminated union: a real `FileEntry`, or a parent navigation action with its own key and no filesystem metadata/path. The action is prepended only if the backend supplies `parent`; it is never part of the listing's entry array, item/folder counts, or real-entry IPC. A real file named `[..]` stays a distinct ordinary entry. Future operation APIs must continue to accept only real entries.
- Enter and double-click on the parent action reuse the same `parent()` operation as Backspace and the toolbar. The operation carries the exited directory's opaque native identity as a desired selection. The parent response restores that child and reveals it through the virtual row offset. If it disappeared, the first real entry is selected; an empty non-root falls back to its parent action, an empty root to no selection. Normal navigation still selects the first real entry when available.
- Retry transfers focus to its existing list synchronously, before removing the error banner. No asynchronous completion changes focus, so intentional moves to another pane/control survive both success and failure. A path-edit revision also prevents completion from overwriting a new unsubmitted address; pure sorting leaves the path editor untouched.
- At narrow pane widths a native select exposes all sort keys plus a direction button. A native details/summary control exposes the selected name/type/exact size/modification time at every width; Alt+Enter opens it from the list and Escape on its summary returns focus. It overlays rather than reducing the list viewport.
- The Windows byte-length check uses `is_multiple_of`, matching the installed Rust toolchain's Clippy rules. Drive/UNC root-parent tests are Windows-gated and remain explicitly unexecuted on Linux.

## Slice 001 second acceptance hardening

- Navigation intent is the requested destination plus its desired selection, independent of the displayed listing. Retry replays that pair unchanged after repeated failures. Only a new navigation replaces it; stale completions cannot commit listings or selections.
- Address editing tracks both an input revision and whether the edit remains active. Completion preserves newer active input. Escape clears editing intent and shows the committed location; a pending navigation can then update it. Submission ends the edit and starts an explicit navigation. Pure sorting never edits the address.
- Responsive sorting retains the existing controls and breakpoint. When CSS hides an owned sort control, its blur handler checks that it has no visible rectangle and no intentional focus destination, then focuses the visible equivalent. Ordinary focus moves do nothing. This avoids resize observers, delayed focus recovery and global focus ownership state.
- Errors use a 40px preview with ellipsis, a separate Retry button and a native details disclosure for the complete message/current path. The nonmodal detail dialog wraps unbroken paths and scrolls within the pane; it overlays the list and leaves the footer accessible. Native details owns its open state so fast opening/closing does not race its asynchronous toggle event.
- These changes are entirely presentation/state fixes. Rust core, native path semantics, IPC contracts, filesystem access and request sequencing are unchanged.

## Slice 001.5 — Window chrome and DPI

- `WindowHeader.svelte` owns the existing application header and desktop controls. Windows/Linux use an undecorated, resizable main window, Tauri's built-in drag/double-click handling and runtime edge/corner resizing. macOS uses the platform configuration override with native traffic lights and an overlay title bar; the header reserves their space. No OS plugin or native interop dependency was added.
- `window-state.ts` observes native maximize and scale state with resize/scale listeners, ignores stale asynchronous reads, and releases listeners even when registration finishes after teardown. These observations only refresh chrome state. The OS/WebView retain ownership of content DPI, window dimensions and rasterization: the application never applies a CSS transform, WebView zoom, resolution heuristic or automatic resize.
- Pointer window controls retain the current DOM focus; keyboard users can focus controls normally and press Escape to return to the active pane. No asynchronous window completion changes pane focus.
- Chrome mutations are restricted to the main desktop window: drag on the three desktop platforms, minimize/toggle-maximize/close on Windows/Linux. Existing read-only default window/event permissions provide state observations. Resize hit testing needs no extra JavaScript capability.
- WSLg is a separate Linux/GTK/WebKitGTK execution path. Its disabled fractional scaling can expose scale 1 for a Windows 150% monitor; its X11 minimized-state notifications can also differ from the actual host state. These are documented and tested at the boundary, without production platform workarounds. See [Slice 001.5](slices/001.5-window-chrome-dpi.md) for measured evidence and native platform limitations.

## Slice 002 — Safe local mutations

- Five narrow commands (`create_directory`, `rename_entry`, `copy_entry`, `move_entry`, `trash_entry`) delegate to `qpanes-core` on Tauri's blocking pool. Mutations accept opaque native directory identifiers or real `Entry` sources. Listings add a native file identity token; mutations reject missing/stale identities and revalidate actual types. Parent navigation actions remain outside the entry/request types. A stopped mutation worker reports an unknown outcome requiring inspection rather than suggesting an immediate retry.
- `cap-std`/`cap-fs-ext` anchor operations to directory handles, reject symlink path components and open recursive children without following links. Linux/macOS publication and moves use Rustix `renameat_with(NOREPLACE)`; Windows uses `SetFileInformationByHandle(FileRenameInfo)` with `ReplaceIfExists = false` and a destination directory handle. There is no check-then-overwrite rename or copy/delete move fallback. Cross-device moves return `cross_device_not_supported`.
- Copy streams through a 64 KiB buffer into an exclusively created `.qpanes-copy-*` staging directory on the destination filesystem. Only completed payloads are published with no replacement. Directory creation/opening cannot authenticate staging ownership. Acquisition rejects already populated staging, and cleanup on every platform removes only empty directories, never their contents. Nonempty staging is retained with a warning or error recovery location for manual review. Recursion rejects links, special entries, device crossings, ancestor loops and its own staging, and has a depth bound. Linux mount IDs additionally exclude bind-mount crossings/aliases. This is not a live-filesystem snapshot or a power-loss transaction. The [slice policy](slices/002-safe-file-operations.md) records metadata and concurrent-namespace limits.
- `trash` is pinned to 5.3.0. Linux enables only its descriptor-based Desktop Portal backend, with defaults disabled; the FreeDesktop backend's copy/delete fallback is deliberately excluded. macOS selects `NsFileManager` and rejects non-UTF-8 paths the dependency cannot represent safely. Windows Trash fails closed because the reviewed integration cannot guarantee recycle-only behavior. QPanes never invokes permanent deletion as a fallback. Portal access adds the existing D-Bus ecosystem instead of implementing the Trash format ourselves.
- The renderer captures a real entry and both pane locations/revisions before opening one native modal operation dialog. A local busy guard prevents duplicate execution, and no operation can start from an input or a parent action. Completion refreshes only affected, still-current pane locations, selecting returned native identifiers where appropriate. Existing navigation request sequencing, independent sort state and virtualization remain in place. No queue, watching, multi-selection, progress engine or chrome/DPI change was introduced; the old read-only badge text now says Local workspace.

## Slice 003 — Process-owned operations

- `qpanes-core::operation_manager` owns one authoritative registry and one standard-library worker thread. A short-held mutex/condition variable protects FIFO admission, explicit state transitions and concurrent snapshots; filesystem I/O runs outside the registry lock. Desktop mutation IPC has one path through this manager. The old five direct mutation commands are removed from the adapter; the underlying core functions remain reusable.
- Tagged immutable intent stores the confirmed native source entry, destination/parent and new name. IDs and timestamps originate in Rust. At most 32 nonterminal and 64 terminal jobs are retained. Up to 64 submission clients retain monotonic sequence high-water marks for the process lifetime: repeated tokens return the original retained job or fail as consumed, including after dismissal/eviction. This bounds memory without allowing an expired duplicate to execute again. Oversized intents are rejected. A fresh renderer attachment counts as a new client; exhausting the attachment limit requires finishing work and restarting the app.
- Copy retains the existing 64 KiB staging/no-replace pipeline. A core observer checks cooperative cancellation and counts successful writes, including partial writes; counters use checked arithmetic. Single-file totals and stream bounds share the opened source metadata. Metadata is revalidated after preparation checkpoints and before payload creation, including each recursive child; detected preparation changes fail before writing that item. Later failures preserve actual successful-write counts. Recursive totals remain unknown without a prescan. File counts increase only after file content/metadata succeed. Monotonic samples produce smoothed speed and optional ETA after warm-up. Registry progress notifications are coalesced to about 10 Hz, with final progress and all lifecycle transitions forced. The frontend expires stale speed/ETA samples.
- A locked publication gate arbitrates cancellation: requests accepted before the gate prevent publication; after the gate cancellation is unavailable and the native result wins. No successfully published data is rolled back. Atomic create/move/rename/Trash jobs can be cancelled while queued/preparing, but not after their primitive starts. Nonempty staging is still never deleted automatically. Cancelled copies with retained staging remain Cancelled with `cancellationCleanupFailed`, a structured native recovery identifier and a location message.
- Failed jobs retain structured errors and do not stop the FIFO. Eligible explicit retries create a new ID and `retryOf`, reuse immutable intent, revalidate current filesystem conditions and allocate new staging. No automatic retry/resume exists. Trash failures and unknown/panicked outcomes are not retryable. Panics are caught at the job boundary in builds that unwind; the existing desktop release `panic = "abort"` remains a process-failure boundary, not a cleanup/rollback guarantee.
- Tauri managed state holds the manager. `operations-changed` events contain only revision invalidations; `list_operations` returns the authoritative bounded complete snapshot. Events suit this low update rate and allow a process-owned job to outlive a renderer attachment; a channel would unnecessarily tie streaming ownership to that attachment. The renderer listens before its initial snapshot, coalesces reads, rejects older revisions and releases even late listener registrations. Complete snapshots reconcile history removal without unbounded tombstones or timer polling. Each actual worker attempt receives a terminal `invalidationRevision`, atomically with a process-wide completion counter that survives history dismissal/eviction; queued cancellations do not advance it. If retained completion stamps cannot cover the interval since the last acknowledged counter, the renderer defers one conservative re-read of its current/arriving pane locations through existing navigation/edit/sort guards. Fully observed intervals retain exact native-directory/subtree invalidation, so unrelated panes stay unchanged. A successful snapshot read acknowledges connection health independently of revision advancement; action-specific failures remain separately visible. Details/cancel/retry/dismiss commands are narrowly typed; the frontend cannot supply results or job state.
- Existing confirmation dialogs close after admission, restoring focus immediately. The bottom Operations dock renders bounded history, real status/progress, errors/warnings, cancellation/retry and terminal dismissal. Terminal namespace jobs carry both exact affected parent directories and old source-directory subtrees for rename/move/Trash. A bounded pure Rust command compares canonical native path components/ancestry; JavaScript never splits opaque IDs or compares lossy labels. A vanished displayed directory reports an unavailable state without redirecting the pane. Invalidation targets only matching displayed/in-flight locations, preserving current selection and focus instead of replaying a submission-time selection. Invalidations wait through navigation, sorting and path editing, then drain without restoring an obsolete location. An Operations action or alert control that owns focus transfers it to the persistent dock toggle before that control disappears or becomes unavailable; ordinary progress and focus outside the dock do not trigger recovery. The title bar and visual tokens remain intact; short-window spacing accommodates the added dock.
- Rust intercepts both window Close and application Exit with active work, including the existing custom Close button. A versioned snapshot exposes confirmation/draining/blocked/ready shutdown state and an opaque attempt identity so reload can recover the prompt. Repeated Close shares the prompt token; every drain, waiter, exit claimant and frontend action must match the current attempt. Cancel and close stops admission, cancels queued jobs and requests copy cancellation. One condition-variable waiter per attempt runs off the UI thread; its own three-second deadline exposes Blocked while unresolved calls continue. Last-worker completion reconciles Draining/Blocked to Ready, preserving recovery warnings, and permits one normal exit claim. Keep working invalidates the attempt and wakes obsolete waiters; no stale callback/action can time out or exit a newer attempt. Explicit Force exit requires the current Blocked token. A prompt whose jobs naturally finish before confirmation remains open with an accurate explicit Close action. Shutdown dialog teardown releases modal inertness synchronously, validates its saved return control, captures a surviving native modal owner even when its disabled child already left BODY focus, and otherwise returns to the current active pane; it leaves an existing external focus target alone. An owned shutdown action hands focus to the dialog before being disabled/replaced during drain/block transitions. Minimize/focus/dock collapse do not affect workers. Jobs are not durable; sudden termination can retain staging and unknown outcomes. No startup cleanup, daemon, database, new dependency or new unsafe Rust was introduced.

## Slice 004 — Daily usability

- **Tabs.** `PanelTabs.svelte` owns one side: heading, tab strip and one mounted `FilePane` per tab (at most 32). Inactive tabs stay mounted but `hidden`, so each keeps its own listing, request sequence, selection, sort, filter, path draft and invalidation guards; switching never re-reads. A hidden element has no scroll box, so scroll is tracked logically and re-applied when shown; the last visible height is retained. Restored inactive tabs load lazily on first display. Row element IDs include the tab ID. Operation invalidations are broadcast to every mounted tab; each applies the existing exact native directory/subtree rules, so only affected tabs re-read. The page reaches only the active tab (`operationSnapshot`, focus, path editing). A panel always keeps one tab; closing activates the right neighbour, else the left. `DirectoryListing.name` (lossy final component, full label for roots) supplies tab labels so JavaScript never splits paths.
- **Quick Filter.** Pure `filter.ts`: NFC normalization plus locale-independent `toLowerCase`, substring match on display names, keys computed once per listing, no IPC per keystroke. Filtering produces the virtualized row model; `[..]` stays first. A filter belongs to its location: navigating elsewhere clears it, re-reading the same location keeps it. Escape (field or list) clears and returns focus to the list.
- **Drag and drop.** Pointer Events, not HTML5 DnD, so behavior does not depend on WebView DnD differences or Tauri's native file-drop handler (left enabled; external drops stay unsupported and never navigate the webview). Only real `file`/`directory` rows of the visible tab can be dragged. The only target is the opposite panel's visible directory view; tab strip, header drag region, source panel and outside the window cancel. Any non-modifier key, blur, pointer cancellation or lost capture cancels. A drop captures the source entry identity and both native locations, rejects same-directory drops and (through the existing pure Rust classifier, failing closed on IPC errors) folder-into-itself/descendant drops, then opens the existing modal operation dialog in a Copy/Move/Cancel mode. The chosen operation uses the unchanged submission path into the OperationManager, which revalidates everything.
- **Shortcuts.** Pure `shortcuts.ts` defines actions, platform defaults, canonical combos (physical modifiers in the order Ctrl, Alt, Shift, Meta), validation, reserved keys, conflicts and override reconciliation. `+page.svelte` has the single window dispatcher; list navigation keys remain fixed in `FilePane`. Nothing dispatches while a dialog, shutdown prompt or drag owns input; in text fields only Quick Filter is honoured. Key repeat is ignored except for tab cycling. Actions only open confirmations or change views. The installed Tauri builds a native menu on macOS only; ⌘Q/W/H/M, ⌥⌘H, ⌃⌘F and the Edit-menu keys are reserved there, and Close tab defaults to ⇧⌘W. No custom native menu or global hotkey exists.
- **Persistence.** `qpanes-core::settings` owns one versioned JSON document (`settings.json` in Tauri's app configuration directory): favorites, shortcut overrides and the tab session, all paths as opaque native identifiers. Load is lenient: missing → defaults; read errors → defaults with persistence disabled; corrupt, oversized, wrong-version or individually invalid content → original preserved as `settings.invalid.json` before reporting warnings (persistence disabled if that fails). Save validates strictly, bounds sizes, writes an exclusive temporary sibling, flushes and renames atomically. The adapter adds `load_settings`, `save_settings` (both serialized by one mutex on the blocking pool) and `probe_directories`; no plugin, database or capability permission was added. The renderer is the live source of truth and saves through one in-flight, coalescing writer, only after a loaded, missing or recovered result; a failed or timed-out load disables saving for the session. Concurrent instances are last-writer-wins. `serde_json` was added to `qpanes-core` (already in the desktop dependency graph). Native test launchers isolate `XDG_CONFIG_HOME`.
